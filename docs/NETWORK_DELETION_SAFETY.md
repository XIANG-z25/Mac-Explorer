# 网络删除安全修复与边界

日期：2026-10-25。针对 PR #30 的 `a1d4e04` 后续修复。所有测试只使用本地临时夹具，不操作真实 NAS。

## 2026-10-26 当前状态

- 应用的网络永久删除入口已暂停：正常准备接口立即拒绝网络项，AppKit 再次检查整个批次；网络项目、混合选择和本地别名均不能触发永久删除或退回本地回收。错误不消耗剪贴板和文件历史。
- 本地回收不受 64 项网络清单上限约束。准备后释放每项父目录 FD，执行前重新打开并复核父目录、条目、卷类型和 FSID；大批量选择不累积句柄。
- 核心引擎的同目录及跨顶层项硬链接删除共享本次操作产生的状态时间记录；每次仍检查身份、内容元数据、权限和链接数变化，保留外部变更检测，且不要求读取文件内容。
- 下方记录属于先前版本。核心引擎及 `KNOWN LIMIT` 夹具继续保留，不表示永久删除已恢复；真实 NAS 安全验收完成前不开放应用入口。
- `python3 -I native/scripts/check-deletion-ui.py` 使用隐藏窗口、临时目录和命名剪贴板检查实际 AppKit 入口，不启动前台应用生命周期。

## 已实现的保护

- 删除入口对全部条目先准备，再展示确认或调用回收站。父目录使用 `realpath` 解析后打开 FD，最终条目使用 `fstatat(..., AT_SYMLINK_NOFOLLOW)`；分类来自实际父目录 FD 的文件系统标志。缓存挂载路径匹配仅作菜单提示，不能决定操作。
- 分类或准备失败时整个批次停止，不把未知状态当作本地回收。普通本地条目也绑定父目录、条目和 FSID，系统回收调用前再次复核，传入已解析父目录下的实际路径。
- `lstat`、`openat`、`fstat`、`fstatfs`、目录枚举和 `unlinkat` 的原始错误保留在错误链中；只有实际身份、清单或挂载不一致使用 `ESTALE`。未知准备失败不再按本地路径猜测隐私授权。
- 网络清单记录名称、身份、mode、size、mtime/ctime 等元数据；先完整复核清单，再执行第一次删除。确认后已新增、替换或修改的节点会导致停止。执行仅遍历确认过的名称；执行期间新增的条目不被纳入删除，目录保留并报告部分失败。
- 失败返回已成功 `unlinkat` 的条目数和根条目是否删除。零变更失败保留 redo；真实永久删除（包括删除子项后失败）清空 redo。只消费实际移除根条目的选择及剪贴板记录。
- 不跟随最终符号链接，不跨不同设备/FSID 的子挂载，不 chmod、强制重试、生成备份或临时隔离目录。权限变化只由临时夹具用于故障注入。

## 资源和性能

- 每批最多 64 个顶层条目；整个准备批次最多 50,000 个清单节点和 16 MiB 累计路径 UTF-8 字节，最大递归深度 128。
- 准备、完整复核和执行各受合作式 60 秒预算及任务取消检查约束。预算不能中断已经阻塞在内核/服务器中的单次系统调用，不承诺硬超时。
- 超限明确停止，不退化为无清单递归。准备和预检超限不会先删除文件；执行阶段的失败会报告已完成数量。
- 清单只读取元数据，不读取/哈希文件内容。每个目录作固定次数的成员读取，不在每个子项删除前反复全量枚举同一大目录。FD 在失败时释放并设置 close-on-exec；深度与批次限制也用于约束 FD 数量。

## 验证接口

普通构建没有可注入网络分类器的构造器、`PreparedDeletion.fixtures` 或 `auditHook`。只有 `build.py --validation` 及网络核心夹具启用 `EXPLORER_DELETION_TESTS`；夹具接口另外限定随机命名的临时根、源的实际父路径范围，并强制检查实际 FD 为本地文件系统。

`check-deletion-api.py` 在未定义验证宏时分别引用这些入口，要求编译拒绝。它验证编译边界，不把 SPI 或注释当作安全隔离。

## 明确保留的限制

**没有消除最终 `fstatat → unlinkat` 之间的竞态。** POSIX `unlinkat` 没有“仅当 inode 仍匹配才删除”的条件参数。即使前面每次检查均成功，其他客户端仍可能在最后检查之后替换同名条目。现有实现不能保证这种情况下替换对象不被删除。

网络确认会简短显示并发替换误删风险。验证版使用最后检查后的专用钩子，确定性复现实际删除引擎中的该窗口；该用例标记 `KNOWN LIMIT`，通过代表成功复现风险，绝不代表获得原子保证。钩子不进入普通构建。

清单也不是文件系统快照或事务：扫描是分时读取，执行期间变化可能在已经删除部分确认节点之后才被发现。数据在原 inode 内变化且服务器没有反映到可见元数据时，也不能视作已获得内容版本保证。本地系统回收使用路径接口，复核与系统调用同样不是一个原子操作。

没有引入未经真实 SMB 验证的临时重命名、隔离目录或自动回滚。这些方案若后续采用，必须单独证明排他性、身份验证、恢复路径、断线及取消行为。维护者应在明确接受剩余并发风险后决定是否合并；若不接受，应停用网络永久删除入口，而不是把当前实现宣传为完全安全。
